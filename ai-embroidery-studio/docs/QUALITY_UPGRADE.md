# 刺繡輪廓與細節檢查報告

日期：2026-10-15。基準：`824c7da`（`embroidery-gate-a`）。

## 已確認的原因與修正

| 問題 | 影響 | 修正 |
| --- | --- | --- |
| 對分類色號做 3×3 中值濾波 | 細線消失、小孔洞被填平、輪廓被磨圓 | 依連通區域大小清理，保持原始前景遮罩 |
| 自動色數只看 95 百分位誤差 | 很小但明顯的點綴顏色被合併 | 另檢查空間連續的高色差區域；仍無法表達時顯示提示 |
| 固定清理小於 0.8 mm 平方的區域，描邊時再次過濾 | 獨立小點與文字重音符號可能消失 | 提供三種細節模式，預設 0.35 mm；取消第二次像素雜點過濾 |
| 去背刪掉全圖所有背景近似色 | 圖案內部白色眼睛或高光變成洞 | 預設只移除外側相連背景；保留全部同色去背選項 |
| 透明度必須佔 1% 才被採用 | 窄透明邊框可能被誤當不透明圖 | 直接辨識透明像素；縮圖採預乘透明度，減少隱藏 RGB 滲色 |
| 中心線骨架再裁掉半個線寬 | 細長圖形端點縮短 | 以端點切線延伸至原圖邊界 |
| 緞面只比寬度與面積估計 | 寬度看似均勻，外形仍可能偏離 | 比對重建輪廓與原輪廓的交集／聯集；低於 90% 改用填針 |
| 重新載入專案會重設去背選項 | 再分析的設定與上次不同 | 將原始分析選項存入設計版本並還原到介面 |

中心線簡化改用毫米尺度，避免 SVG 座標單位影響平滑程度。舊幾何資料在重新規劃時升級，
既有專案的原始分析結果不會在背景自動改寫。針跡密度設定與圖片細節設定分開顯示。

另修正 Windows 編譯器路徑的反斜線解析、必要的子程序環境與逾時後清理子程序，
使本機流程測試可以執行；Linux 程序群組行為維持既有方式。

## 如何使用

1. 開啟既有圖片專案，在「圖片轉向量」選「保留細節」。
2. 圖內白色需刺繡時選「只移除外側背景」；字母的封閉空洞需透出布料時選「移除所有同色區域」。透明 PNG 依透明度判斷。
3. 點「以這些設定重新分析」，比對原圖、分色結果和區域圖。此動作會建立新版本，手動改色、隱藏區域與針法需重新確認。
4. 再編譯並檢查針跡預覽。過小的細節可能需要放大成品尺寸；增加針跡密度不能恢復已刪除的圖形。

## 可重現驗證

```text
python -m pytest -q -rs
python tools/compare_import_quality.py --baseline-ref 824c7da
cd apps/web
npm ci --ignore-scripts
npm run typecheck
npm run build
```

新增測試涵蓋色號清理、細線保留、透明孔洞、小色塊、獨立小點、去背範圍、透明縮圖、
色數不足提示、細節選項保存、端點長度與緞面輪廓相似度。
比較工具輸出 `out/quality/comparison.png` 和 JSON，展示相同合成測試圖在升級前後的圖片處理結果；
它不是機繡成品照片，也不是 DST/PES 的針跡模擬。

完整流程測試使用測試用編譯器驗證排程、檔案格式、讀回驗證及匯出，不代表真實 Ink/Stitch 的針跡品質。
本次結果：105 個測試通過，8 個跳過；TypeScript 檢查與正式版建置通過。
跳過項目為 5 個真實 Ink/Stitch 測試、1 個 Postgres 測試，以及 2 個需要 `huggingface_hub` 的部署工具測試。
本機尚無 `INKSTITCH_CMD` 與真實 Postgres 測試連線；Supabase 的儲存測試使用 mock，未連接線上帳號。
部署後需在原有 Ink/Stitch 3.3.0 環境執行真實編譯測試，再以使用者的失真原圖與指定尺寸進行比對和試繡。
這次未取得使用者的實際問題圖片，因此驗證以合成案例與儲存庫既有測試圖為準。

緞面描邊的基本使用方式參考 [Ink/Stitch 官方 Satin Column 文件](https://inkstitch.org/docs/stitches/satin-column/)。
目前仍使用固定寬度的中心線緞面；寬度變化大或輪廓不符的圖形回到填針，沒有聲稱能自動完成所有複雜文字的專業打版。
